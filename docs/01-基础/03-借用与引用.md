# 借用与引用（Borrowing & References）

## 一句话理解

> **引用（Reference）让你"借用"值而不拿走所有权。**

借用解决了上一节的问题——你不需要每次函数调用都把所有权传过去再传回来。

## 不可变引用 `&T`

```rust
fn calculate_length(s: &String) -> usize {
    s.len()           // 可以读，不能改
}

let s = String::from("你好");
let len = calculate_length(&s);
println!("{}", s);    // ✅ s 依然可用
```

- `&s` 创建了一个指向 `s` 的引用
- 引用本身也是值，存储在栈上（就是一个指针）
- 函数拿到的是"借来的"，没有所有权，所以离开函数时不会 drop

## 可变引用 `&mut T`

```rust
fn change_message(s: &mut String) {
    s.push_str(", world!");
}

let mut message = String::from("hello");
change_message(&mut message);
println!("{}", message);  // ✅ "hello, world!"
```

- 需要 `&mut` 才能通过引用修改值
- 调用处也必须是 `&mut message`（且 `message` 本身必须是 `mut`）

## 借用规则（重中之重！）

### 规则一：任意时刻，只能有一个可变引用 OR 多个不可变引用

```rust
let mut v = vec![1, 2, 3];
let first = &v[0];          // ✅ 不可变借用
// v.push(4);               // ❌ 同时存在不可变引用和可变借用！
println!("{}", first);      // ✅ 借用结束
v.push(4);                  // ✅ 现在可以了
```

```rust
let mut s = String::from("hello");
let r1 = &s;      // ✅
let r2 = &s;      // ✅ 多个不可变引用没问题
let r3 = &mut s;  // ❌ 不可变引用 r1, r2 还存在时不能创建可变引用
```

### 规则二：引用不能比它指向的值活得更久

```rust
// ❌ 悬垂引用（dangling reference）—— 编译错误
fn dangle() -> &String {
    let s = String::from("hello");
    &s
} // s 被 drop，引用指向无效内存
```

编译器报错：`missing lifetime specifier`——这正是 Rust 防止悬垂指针的方式。

### 规则三：引用的作用域

- 不可变引用 `&T` 的作用域从创建到最后一次使用
- 可变引用 `&mut T` 的作用域从创建到下次使用前
- 这被称为 **NLL（Non-Lexical Lifetimes）**——非词法生命周期

```rust
let mut name = String::from("Alice");
let r = &name;              // 不可变引用开始
println!("{}", r);          // 最后一次使用，不可变引用结束
let r2 = &mut name;         // ✅ 因为之前 r 已经不再被使用
r2.push_str(" Smith");
```

NLL 让代码更灵活，你不是被"大括号"限制，而是被"实际使用"限制。

## 悬垂引用（Dangling References）

这是 Rust 在编译期消除的内存 bug：

```rust
// 这个函数❌不可能通过编译
// fn dangle() -> &String {
//     let s = String::from("hello");
//     &s
// }

// ✅ 正确方式：返回 String 本身，转移所有权
fn no_dangle() -> String {
    String::from("hello")
}
```

**在其他语言中**，返回局部变量的引用是未定义行为，只能靠程序员自觉。在 Rust 中，**编译器直接拒绝**。

## 引用与解引用

```rust
let x = 42;
let ref_x = &x;          // 引用
println!("{}", *ref_x);  // 解引用：*ref_x = 42

// 自动解引用（方法调用时自动发生）
// 当你调用 ref_x.to_string() 时，Rust 自动插入 *
```

## `&str` vs `&String`

这是一个常见的困惑点：

```rust
let s = String::from("hello");

// &String 是对 String 的引用
fn take_ref(s: &String) {
    println!("{}", s);
}

// &str 是字符串切片引用（更通用的类型）
fn take_str(s: &str) {
    println!("{}", s);
}

take_ref(&s);    // ✅
take_str(&s);    // ✅ &String 可以自动转为 &str（Deref 强制转换）

let s2 = "hello";        // 字符串字面量是 &str
take_str(s2);            // ✅
// take_ref(s2);         // ❌ &str 不能变成 &String
```

**建议**：函数参数用 `&str` 而不是 `&String`，更通用。

## 切片引用（Slice）

切片是数组/向量的一段连续区域的引用：

```rust
let arr = [1, 2, 3, 4, 5];
let slice = &arr[1..4];        // &[i32] 类型
println!("{:?}", slice);        // [2, 3, 4]

let s = String::from("hello world");
let hello = &s[0..5];          // "hello"（&str 类型）
let world = &s[6..11];         // "world"

// &str 本质上就是指向 String 堆内存某段区域的切片引用
```

## 内部可变性（提前了解）

借用规则是编译期强制检查的。但有些场景需要在运行时绕过它：

- `Cell<T>`：允许 Copy 类型的内部可变性
- `RefCell<T>`：允许运行时借用检查（不是编译期）
- `Mutex<T>`：线程安全的内部可变性

这些是**进阶内容**，但了解它们的存在很重要——它们说明 Rust 的设计是务实的：**编译期静态检查 + 运行时动态检查**的组合可以覆盖所有场景。

## 借用 vs 所有权：何时用哪个？

| 场景 | 推荐 |
|------|------|
| 只需读数据 | `&T`（不可变引用） |
| 需要修改数据 | `&mut T`（可变引用） |
| 需要取得数据所有权 | 直接传值（移动） |
| 需要在多处共享 | `Rc<T>` / `Arc<T>`（后续学习） |

**黄金法则**：能借用就借用，只在确实需要所有权时才移动。
