# 错误处理（Error Handling）

> Rust 没有传统语言中的 try/catch，它用 `Result<T, E>` 枚举来显式处理错误。

## 是什么

Rust 的错误处理核心是两个枚举：

```rust
enum Result<T, E> {
    Ok(T),   // 操作成功，包含值
    Err(E),  // 操作失败，包含错误信息
}
```

`Result` 和之前学过的 `Option` 几乎一样——`Option` 表示"可能有值也可能没有"，`Result` 表示"可能成功也可能失败"。

## 怎么用

### 三种处理方式

| 方式 | 行为 |
|------|------|
| `.unwrap()` | 成功时返回值，失败时 panic 崩溃 |
| `.expect("消息")` | 类似 `.unwrap()`，但崩溃时输出自定义消息 |
| `match` / 组合子 | 显式处理成功和失败两种情况 |

### `?` 操作符

`?` 是 Rust 错误处理的精髓，它是 match 的语法糖：

```rust
// 用 ? 的写法
fn read_file(path: &str) -> Result<String, io::Error> {
    let content = fs::read_to_string(path)?;  // Err 时直接 return 出去
    Ok(content)
}

// 等价展开
fn read_file(path: &str) -> Result<String, io::Error> {
    let content = match fs::read_to_string(path) {
        Ok(c) => c,
        Err(e) => return Err(e),
    };
    Ok(content)
}
```

## 为什么

Rust 没有 null 和异常（exception），这是刻意的设计决策：

- **没有 null** → 用 `Option<T>` 表示"可能没值"
- **没有异常** → 用 `Result<T, E>` 表示"可能失败"

你**必须**显式处理错误，编译器不让你忽略。这听起来麻烦，但在大型项目中，它彻底消灭了"忘记处理错误"这类 bug。

## 常见陷阱

### 1. `.unwrap()` 滥用

```rust
let content = fs::read_to_string(path).unwrap();  // ❌ 文件不存在就崩溃
let content = fs::read_to_string(path)?;           // ✅ 把错误传给调用者
```

`.unwrap()` 只应该在以下场景出现：
- 测试代码
- prototype / 一次性脚本
- **你 100% 确定不会失败**（极少）

### 2. 线程中的 `.unwrap()`

```rust
handle.join().unwrap();  // ❌ 子线程 panic 会导致主线程也崩溃
```

线程间错误传播需要更谨慎的处理。

### 3. `?` 的类型约束

`?` 只能用在**返回 `Result`** 的函数里。如果在 `main` 函数（返回 `()`）中使用 `?`，会编译错误。

```rust
fn main() {
    let content = fs::read_to_string("file.txt")?;  // ❌ 编译错误
}
```

Rust 允许 `main` 返回 `Result`，但要写成：

```rust
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let content = fs::read_to_string("file.txt")?;  // ✅
    Ok(())
}
```

## 第一课回顾

我们在词频统计器中发现了两个隐患：

1. `handle.join().unwrap()` — 子线程 panic 会拖垮整个程序
2. 混用 `?`（优雅传播）和 `.unwrap()`（不成就炸）——风格不统一

已经确认 `count_words` 中的 `?` 是好的做法。

## 第二课实战：改造 handle.join().unwrap()

### 问题

`handle.join()` 返回的是嵌套两层的 `Result`：

| 层级 | 类型 | 含义 |
|------|------|------|
| 外层 | `Result<T, Box<dyn Any>>` | 线程是否正常结束 |
| 内层 | `(String, Result<usize, io::Error>)` | 线程函数的返回值 |

原代码用一个 `let (filename, result) = handle.join().unwrap();` 直接拆开两层——如果线程 panic 就崩了。

### 改造方案

用两层 `match` 分别处理每一层的结果：

```rust
match handle.join() {
    Ok((filename, result)) => {
        match result {
            Ok(count) => {
                println!("[{}] 单词数: {}", filename, count);
                total_words += count;
            }
            Err(e) => eprintln!("[{}] 读取失败: {}", filename, e),
        }
    }
    Err(_) => eprintln!("线程崩溃了"),
}
```

### 关键认识

- `handle.join()` 返回 `Result<T, Box<dyn Any>>`，`T` 是线程闭包的返回值类型
- 线程闭包返回 `(String, Result<usize, io::Error>)`，所以 join 后是 `Result<(String, Result<usize, io::Error>), Box<dyn Any>>`
- 两层 Result 都要处理——这才是完全的错误处理

### 实验验证

1. 把 `?` 换成 `.unwrap()` → 程序在文件不存在时直接 panic 崩溃
2. 在子线程里加 `panic!("模拟崩溃")` → `handle.join().unwrap()` 让整个程序崩溃，换成 match 后能安全捕获

## 第三课：深入理解 `?` 操作符

### `?` 的本质

`?` 是 `match` 的语法糖，展开后等价于：

```rust
// 你写的
let content = fs::read_to_string(path)?;

// 编译器展开的
let content = match fs::read_to_string(path) {
    Ok(v) => v,
    Err(e) => return Err(e.into()),  // into() 自动调用 From trait 转换错误类型
};
```

### 适用条件

`?` **只能在返回 `Result` 或 `Option` 的函数/闭包中使用**。因为出错时它执行的是 `return Err(...)`——如果函数不返回 Result，没有 Err 可以 return。

### 验证结果

| 尝试 | 结果 | 原因 |
|------|------|------|
| 在线程闭包中用 `?` | ❌ 编译错误 | 闭包返回 `(String, Result)`，不是 `Result` |
| `main` 返回 `Result<(), Box<dyn Error>>` 后用 `?` | ✅ 编译通过 | main 返回 Result，`?` 可以正常工作 |

### `Box<dyn std::error::Error>` 是什么

`Box<dyn std::error::Error>` 是"类型擦除的错误装箱"：

- `Box<dyn Error>` 可以**装下任何实现了 `Error` trait 的类型**
- 使用 `?` 时，不同类型错误（`io::Error`、`ParseIntError` 等）会自动通过 `From` 转换成 `Box<dyn Error>`
- 适合 `main` 函数和上层应用，因为不在乎具体错误类型，只想统一传播

```rust
// 可以同时处理多种错误类型
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let content = fs::read_to_string("file.txt")?;  // io::Error
    let num: i32 = content.trim().parse()?;          // ParseIntError
    Ok(())
}
```

## 第四课：Result 组合子

### 常用方法

| 方法 | 输入 | 输出 | 场景 |
|------|------|------|------|
| `.map(f)` | `Ok(v)` → `Ok(f(v))` | `Result<U, E>` | 只变换成功的值 |
| `.unwrap_or(d)` | `Ok(v)` → `v`，`Err` → `d` | `T` | 失败时给默认值 |
| `.map_err(f)` | `Err(e)` → `Err(f(e))` | `Result<T, F>` | 变换错误类型 |
| `.and_then(f)` | `Ok(v)` → `f(v)` | `Result<U, E>` | 链式调用，f 也返回 Result |

```rust
let r: Result<usize, io::Error> = Ok(5);

let doubled = r.map(|n| n * 2);        // ✅ Ok(10)
let value = r.unwrap_or(0);            // ❌ r 已被 map 消耗
let value2 = Ok(5_usize).unwrap_or(0); // ✅ 5

// and_then 示例
Ok(5).and_then(|n| {
    if n > 0 { Ok(n * 2) } else { Err("负数了") }
});
```

### `map()` 消耗所有权

`.map()` 会消费（consume）原来的 `Result`，之后不能再使用原变量。

```rust
let r: Result<usize, io::Error> = Ok(5);
let doubled = r.map(|n| n * 2);   // r 被消耗
// r.unwrap_or(0);                // ❌ 编译错误：r 已移走
```

### 闭包返回值陷阱

Rust 中，块的最后一行如果没有分号就是返回值：

```rust
thread::spawn(move || {
    (file, count)   // ✅ 闭包返回 (String, Result)
});

thread::spawn(move || {
    (file, count);  // ❌ 闭包返回 ()，分号让元组变语句
});
```

### 线程闭包的简化

原始代码用了两层 match：
```rust
// 原始：7 行
match count_words(&file) {
    Ok(count) => (file, Ok(count)),
    Err(e) => (file, Err(e)),
}

// 简化：3 行（先计算再放元组）
let count = count_words(&file);
(file, count)

## 第五课：自定义错误类型

### 为什么需要自定义错误

标准错误类型（`io::Error`）只能表示 I/O 错误。业务中经常需要区分不同错误场景：

| 场景 | 应该用什么错误 |
|------|---------------|
| 文件不存在 | `Io(io::Error)` |
| 文件是空的 | `EmptyFile(String)` |

自定义错误就是一个枚举，每个变体代表一种错误场景。

### 手动实现 vs thiserror 自动实现

手动实现需要写 4 个 trait：

```rust
// 1. Debug 可以 derive
#[derive(Debug)]
enum WordCounterError {
    Io(std::io::Error),
    EmptyFile(String),
}

// 2. Display 必须手动实现
impl fmt::Display for WordCounterError { ... }

// 3. Error trait 必须手动实现
impl std::error::Error for WordCounterError { ... }

// 4. From 转换必须手动实现
impl From<std::io::Error> for WordCounterError { ... }
```

用 `thiserror` 后：

```rust
#[derive(Debug, thiserror::Error)]
enum WordCounterError {
    #[error("I/O 错误: {0}")]
    Io(#[from] std::io::Error),

    #[error("文件是空的: {0}")]
    EmptyFile(String),
}
```

| | 手动 | thiserror |
|--|------|-----------|
| 代码行数 | ~17 行 | ~7 行 |
| 宏展开 | 无 | `#[error("...")]` 生成 Display |
| From 转换 | 手写 `impl From` | `#[from]` 自动生成 |

### 使用自定义错误

```rust
fn count_words(path: &str) -> Result<usize, WordCounterError> {
    let content = fs::read_to_string(path)?;  // io::Error → WordCounterError::Io
    if count == 0 {
        return Err(WordCounterError::EmptyFile(path.to_string()));
    }
    Ok(count)
}
```

关键：`?` 运算符会自动调用 `From` trait 把 `io::Error` 转换成 `WordCounterError::Io`。
